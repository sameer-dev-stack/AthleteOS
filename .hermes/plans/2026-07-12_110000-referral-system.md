# Referral System — Complete Build Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Make AthleteOS's referral system production-complete and functional: a standard, conversion-gated, two-sided referral program with link attribution, a real Pro reward that actually unlocks Pro, a full dashboard, social share, funnel analytics, and fraud guards — built on the *existing* schema, not a rewrite.

**Architecture:** Adopt the **universal referral model** used by Dropbox / Uber / Airbnb / Stripe: (1) every user gets a unique shareable link `app/r/CODE`; (2) a first-touch cookie attributes the click for 30 days; (3) when the referred user **completes a real conversion** (onboarding + published card), BOTH sides are rewarded; (4) a dashboard shows link, stats, history, and leaderboard; (5) sharing uses the native share sheet + social deep links; (6) a click→signup→conversion funnel is tracked; (7) fraud guards (self-referral block, one-referral-per-person, reward on conversion not signup). We reuse `referral_codes`, `referrals`, `profiles.referred_by`, `profiles.extended_pro_until` and only *extend* them. The critical fix: wire `extended_pro_until` into plan resolution so the reward actually grants Pro.

**Tech Stack:** Next.js 14 App Router, Supabase (Postgres + RLS + `SECURITY DEFINER` RPC), TypeScript, Tailwind (dark, single accent `#C6FF3D`), Zod, existing server-action pattern.

## 1. Architecture — the standard model (don't reinvent)

```
Referrer shares /r/CODE ──▶ Referred clicks (cookie set, click tracked)
        │
        ▼
   /auth/sign-up ──▶ signs up ──▶ onboarding ──▶ publishes card (CONVERSION)
        │                                              │
        └────────── recordReferral() ─────────────────┘
                       │
                       ├─ status: pending → (on conversion verified) → completed
                       ├─ grant_pro_reward(referrer)      [+REWARD_DAYS to extended_pro_until]
```

```sql
-- Referral funnel analytics + function hardening
-- Run in Supabase SQL Editor, then re-run supabase schema regen.

CREATE TABLE IF NOT EXISTS referral_clicks (
  id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  code TEXT NOT NULL REFERENCES referral_codes(code) ON DELETE CASCADE,
  referrer_id UUID REFERENCES profiles(id) ON DELETE CASCADE NOT NULL,
  ip_hash TEXT,
  user_agent TEXT,
  created_at TIMESTAMPTZ DEFAULT NOW() NOT NULL
);

CREATE INDEX IF NOT EXISTS idx_referral_clicks_code ON referral_clicks(code);
CREATE INDEX IF NOT EXISTS idx_referral_clicks_referrer ON referral_clicks(referrer_id);

ALTER TABLE referral_clicks ENABLE ROW LEVEL SECURITY;

-- Referrers can read their own click counts (aggregate only via RPC; direct select scoped)
CREATE POLICY "Referrers read own clicks"
  ON referral_clicks FOR SELECT
  USING (auth.uid() = referrer_id);

-- Harden grant_pro_reward: set search_path (PROJECT.md D13)
CREATE OR REPLACE FUNCTION grant_pro_reward(referrer_uuid UUID)
RETURNS VOID AS $$
BEGIN
  UPDATE profiles
  SET extended_pro_until = CASE
    WHEN extended_pro_until IS NULL OR extended_pro_until < NOW() THEN
      NOW() + INTERVAL '7 days'
    ELSE
      extended_pro_until + INTERVAL '7 days'
  END
  WHERE id = referrer_uuid;
END;
$$ LANGUAGE plpgsql SECURITY DEFINER SET search_path = public, pg_catalog;
```

## 3. Reward resolution — make the reward real (Task 4–5)

### Task 4: `getEffectivePlan` helper

**Objective:** A single source of truth for "is this user Pro right now" that honors `extended_pro_until`.

**Files:**
- Create: `lib/actions/plan.ts`

**Step 1: Write**
```ts
"use server";
import { createClient } from "@/lib/supabase/server";

export type EffectivePlan = "free" | "pro" | "elite";

export async function getEffectivePlan(): Promise<EffectivePlan> {
  try {
    const supabase = await createClient();
    const { data: { user } } = await supabase.auth.getUser();
    if (!user) return "free";

    const { data } = await supabase
      .from("profiles")
      .select("plan, extended_pro_until")
      .eq("id", user.id)
      .single();

    const plan = data?.plan;
    if (plan === "pro" || plan === "elite") return plan;

    const until = data?.extended_pro_until;
    if (until && new Date(until).getTime() > Date.now()) return "pro";
    return "free";
  } catch {
    return "free";
  }
}
```

```ts
export async function trackReferralClick(code: string, ipHash?: string | null, ua?: string | null) {
  try {
    const admin = createAdmin();
    const { data: row } = await admin
      .from("referral_codes")
      .select("user_id, code")
      .ilike("code", code)
      .eq("is_active", true)
      .single();
    if (!row) return;
    await admin.from("referral_clicks").insert({
      code: row.code,
      referrer_id: row.user_id,
      ip_hash: ipHash ?? null,
      user_agent: ua ?? null,
    });
  } catch (err) {
    console.error("[referrals] trackReferralClick error:", err);
  }
}
```

```ts
export async function getReferralFunnel() {
  const supabase = await createClient();
  const { data: { user } } = await supabase.auth.getUser();
  if (!user) return { clicks: 0, signups: 0, conversions: 0 };
  const admin = createAdmin();
  const codeRow = (await admin.from("referral_codes").select("code").eq("user_id", user.id).single()).data;
  const code = codeRow?.code;
  if (!code) return { clicks: 0, signups: 0, conversions: 0 };
  const { count: clicks } = await admin.from("referral_clicks").select("id", { count: "exact", head: true }).eq("code", code);
  const { count: conversions } = await admin.from("referrals").select("id", { count: "exact", head: true }).eq("referrer_id", user.id).eq("status", "completed");
  // signups ≈ conversions here (reward gated on conversion); show clicks vs conversions
  return { clicks: clicks ?? 0, signups: conversions ?? 0, conversions: conversions ?? 0 };
}

export async function getReferralLeaderboard(limit = 10) {
  const admin = createAdmin();
  const { data } = await admin
    .from("referrals")
    .select("referrer_id")
    .eq("status", "completed");
  // aggregate in JS (small N) or add a SQL view; map to profile names
  const counts = new Map<string, number>();
  data?.forEach((r) => counts.set(r.referrer_id, (counts.get(r.referrer_id) ?? 0) + 1));
  const top = [...counts.entries()].sort((a, b) => b[1] - a[1]).slice(0, limit);
  const ids = top.map((t) => t[0]);
  const { data: profiles } = await admin.from("profiles").select("id, full_name, avatar_url").in("id", ids);
  const pm = new Map(profiles?.map((p) => [p.id, p]) ?? []);
  return top.map(([id, count]) => ({
    id,
    name: pm.get(id)?.full_name ?? "Athlete",
    avatar: pm.get(id)?.avatar_url ?? null,
    referrals: count,
  }));
}
```

## 8. Risks / Tradeoffs / Open Questions

- **Reward timing:** Currently gated on `onboarding_completed` + `profile_published` (called together in `onboarding/page.tsx`). This is a reasonable conversion event. If you want stricter anti-fraud, gate reward on a later signal (first tip, or N days account age). Default: keep current gate, add note.
- **Two-sided amount:** Default 7/7. If you want referred to get less/more, parameterize `grant_pro_reward(referrer_uuid, days)`.
- **`getEffectivePlan` call sites:** Must grep all `plan === "pro"` gating (billing, feature flags, middleware) and route through it — otherwise referral Pro won't unlock those surfaces. This is the highest-risk integration step.
- **No staging:** e2e hits prod; verify manually on a test account before relying on prod audit.
- **`profiles.extended_pro_until` vs Stripe `plan`:** They are independent Pro grants. `getEffectivePlan` ORs them — correct. Ensure Stripe webhook downgrade (`plan=free`) doesn't wipe `extended_pro_until` (it shouldn't; separate column).
- **GDPR:** `referral_clicks.ip_hash` stores a hash only (never raw IP) — consistent with existing analytics posture.
